# 設計哲学と共通ルール (`_common`)

このディレクトリのルールは、すべてのプロジェクトで共通して適用される「エージェントの基本人格」を定義します。

## 1. コミュニケーションと言語設定
- **思考・対話**: すべての思考プロセス、チャット応答、Task UI（TaskName, Status等）は**日本語**で行う。
- **ドキュメント**: 生成するドキュメント（readme.md, walkthrough.md, implementation_plan.md等）の本文はすべて**日本語**で記述する。
- **コードコメント**: コード内のコメントも技術的な慣習に反しない限り**日本語**で記述する。

## 2. 設計思想（疎結合と可読性）
- **疎結合 (Loose Coupling)**:
    - 機能単位でモジュール化し、互いの依存関係を最小限に抑える。
    - グローバル変数の多用を避け、引数や設定クラスを介したデータ受け渡しを行う。
- **可読性優先 (Readability First)**:
    - 誰が見ても一目で意図が伝わるコードを優先する。
    - 短くトリッキーなコードよりも、長くても構造が明快なコードを選択する。
    - 適切な変数名、関数名を命名し、マジックナンバーを排除する。

## 3. 仕様・設計ドキュメントの管理
プロジェクトを進行する際、以下の2層のドキュメントを維持・参照し、実装との整合性を保つ。

- **仕様概要書 (`SpecSummaryYYYYMMDD.txt`)**:
    - **役割**: ユーザーからエージェントへの「最上位の指示書」。プロジェクトの目的、全体構成、主要な仕様目標を記述する。
    - **運用**: 実装中に全体方針の迷いが生じた際、常に立ち返る「真実のソース」とする。
- **設計仕様書 (`docs/*.md`)**:
    - **役割**: 各モジュール（`architecture.md`, `backend_pdf_service.md`, `frontend_ui_state.md` 等）の設計内容・方針・制限事項を記述する。
    - **運用**: 重要なアーキテクチャの決定やインターフェースの合意事項を記録・参照する。実装の細部はコードの可読性とテストコードを第一義とし、設計書の更新は重要な仕様変更時に留めて過剰な二重管理を防ぐ。

## 4. 開発プロセスと透明性
- **プロアクティブな確認**: 仕様の不明点や複数の実装選択肢がある場合は、勝手に決め打ちせずチャットで端的に確認する。
- **簡潔なコミュニケーション**: ユーザーへの確認や相談は、チャット上で要点を箇条書きや選択肢の形式で端的に提示する（個別のQAファイル作成等の形式的手順は不要）。
- **進捗の可視化**: 複数ステップにまたがる大きな作業を行う際は、作業の区切りで「完了した作業」「現在の状況」「次の予定」を簡潔に報告する。
- **段階的な実装**: 大きな機能は小さなステップに分割し、ステップごとにテストや動作確認を行う。
- **エラーハンドリング**: 「正常系」だけでなく、エラー時の挙動（ログ出力、リカバー処理）を考慮して設計する。

## 5. リファクタリング方針と安全確保

個人開発の機動力を損なわないよう、過剰な事前文書化フローは行わず、**テスト自動化とGitの変更追跡**を安全弁として実用的に進める。

### 基本原則
1. **テスト駆動の安全性**: リファクタリング前に既存テスト（`go test`, `bun test` 等）がパスすることを確認し、必要に応じてテストを追加してから変更する。
2. **段階的・小刻みな変更**: 動作する状態を壊さないよう、小さなステップで変更を積み重ねる。
3. **Gitによる差分管理**: 変更差分を `git diff` で常に把握し、いつでも安全に巻き戻せる状態を維持する。
4. **削除コードの意図確認**: 既存コードを削除する際は、その用途や過去の意図（バグ回避など）を考慮し、安易に削除しない。
5. **アーキテクチャ規模の変更時のみ事前相談**: 広範なモジュール再編や公開APIの変更など、影響が大きい場合のみチャット上で方針を事前に相談・合意する。

## 6. ファイル操作と Git 管理
- **破壊的変更の警告**: 既存の大規模なコードを削除・置換する場合は、その理由と影響を事前に説明する。
- **ディレクトリ構成の維持**: プロジェクト独自のフォルダ構造を尊重し、勝手に新しいトップレベルフォルダを作成しない。
- **リポジトリの清潔さ**: 作業用の一時ファイルを作成した場合は放置せず、タスク完了時にクリーンアップする。
